# 真实 Embedding 检索对照：局部收益，必要性证据不足

**结论：等权混合检索在 8 道场景题上提高了首位命中与证据支撑，但在 8 道改写题上的 MRR 增益低于预设门槛，术语题还有回退。当前不能把混合方案宣传为稳定优于单路检索。** 三条路径对 4 道无答案题全部返回候选，需单独治理拒答。

## 实验与证据

- [预冻结协议](real-retrieval-protocol-2026-09-17.md)，最终 Run ID `20260917-real-embedding-final`；[manifest](evidence/real-retrieval-20260917-final/manifest.json) 记录基线提交 `61088e1`、被测脚本源码散列、语料/留出集/模型 SHA、运行环境及容器镜像 ID。[逐问原始结果](evidence/real-retrieval-20260917-final/raw.json)、[汇总](evidence/real-retrieval-20260917-final/summary.json)、[模型统计](evidence/real-retrieval-20260917-final/model-stats.json) 均已归档。
- 10 篇项目内合成训练文档，10 个子块；留出集 28 问：术语、改写、场景各 8，无答案 4。标签与原有诊断问集分离，首次跑分前冻结 SHA-256；标签尚无独立领域专家盲审。这是小语料机制实验，不能代表真实用户分布。
- 实际调用现有 `KnowledgeIngestionService`、`HybridRetrievalService`，以 Elasticsearch BM25、pgvector 向量、等权 RRF 混合单独执行。Embedding 为公开的 [多语言 MiniLM 384 维模型](https://huggingface.co/sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2) 的固定量化 ONNX 版本，在本机 CPU/loopback 推理；它是学得的语义模型，不是默认哈希向量。没有调用外部商业 Embedding API。
- 每条路径先预热每问一次，之后轮换路径顺序做 3 轮。质量分数按 28 个**唯一问题**计算，三轮排名一致；延迟按各路径 84 次顺序服务调用计算。Windows、Java 25.0.2、Python 3.14.3、Docker Desktop 29.7.2，均为本地隔离 Testcontainers。索引构建约 10.45 s，不包含在查询 P95 中。

## 判断和下一步

按协议，混合方案需在改写、场景两层的 MRR 均比两个单路方案至少高 0.05，且召回、证据支撑不退化，P95 不超过 BM25 两倍。场景题相对最优单路提高 `0.0625`，但改写题只比 BM25 高 `0.0313`，术语题支撑@1 比 BM25 低 `12.5` 个百分点。三轮排名一致、P95 护栏达标也不能抵消质量门槛未过。保留现有实现供继续比较，暂不将它写成已证明必要的架构优势。

后续优先级：

1. **P0 无答案控制**：加入明确的证据门槛或拒答决策，用无答案及近邻干扰题验证潜在误引率下降，同时守住可回答题召回。
2. **P1 扩大并重审留出集**：引入经授权的更大真实语料、长文/过期/撤销文档和独立领域标注者；把单相关来源扩展到多相关段落，避免 R@5 全部饱和；对最终回答做盲审引用支撑。
3. **P1 重做成本与收益取舍**：在固定新留出集上复核 BM25、向量、混合和混合+rerank 的质量/延迟/资源；只有通过预设门槛后再考虑改变默认路径。
