# 训练写操作统一并发控制

日期：2026-09-17；变更前基线：`8be674a`。无数据库迁移、无 API 格式变更。

## 问题与实现

原 `addExercise` 使用普通查询检查 IN_PROGRESS，然后读取最大动作序号并插入。事务 A 检查通过后，事务 B 可以完成/取消训练；A 随后仍可能追加动作。两个添加请求也可能读到同一个最大序号，最终由唯一约束拒绝其中一个。仅增加 `@Transactional` 无法消除这些读写交错。

现在已有训练的写操作统一通过 `WorkoutRepository.lockOwned(userId, workoutId)` 执行带 owner 条件的 `SELECT ... FOR UPDATE`，直接返回锁定的 Workout：

1. 由 Spring 代理开启事务。
2. 锁住所属 Workout；不存在或不属于当前用户时返回 404。
3. 在持锁期间检查最新状态，再读写动作、组、回执或反馈。
4. 提交/回滚后释放锁。后到请求等待后重新判断，而不是使用等待前的状态。

新增动作、加组、改组、删组、完成、取消、离线恢复和反馈均使用同一仓储入口；移除回执仓储中重复的父行锁实现。顺序为 Workout → WorkoutExercise（加组时原有子行锁）→ 子表写入，避免不同入口反向获取这些锁。不同 Workout 使用不同父行，不引入应用级全局锁。

开始训练时尚无 Workout 可锁，继续锁用户行，并保留“同一用户至多一个进行中训练”的部分唯一索引；这与已有训练的父行锁协议分别处理创建与修改。

## 保留的业务语义

| 场景 | 行为 |
|---|---|
| 进行中训练写动作/组 | 获取父行锁后允许；并发新增动作串行分配序号 |
| 完成/取消先提交，动作或组写入后获得锁 | 拒绝，分别返回 `WORKOUT_ALREADY_COMPLETED` / `WORKOUT_CANCELLED`，HTTP 409 |
| 重复完成 / 重复取消 | 幂等返回；重复完成不新增 Outbox 事件 |
| 完成与取消竞争 | 先取得锁并提交者决定终态，另一个操作返回 409 |
| 已成功的离线操作重放 | 锁后先查询回执，即使训练已结束仍返回原响应，不重新写组 |
| 新离线操作写入已结束训练 | 无历史回执，进入正常状态校验并返回 409 |
| 同一操作 ID 携带不同内容 | 保留 `IDEMPOTENCY_KEY_REUSED` 冲突语义 |
| 反馈 | 仅 COMPLETED 可写；同训练反馈在父行锁下串行 Upsert，后提交更新生效 |

完成接口附带反馈仍由控制器先完成训练、再单独提交反馈，是两个事务；本次没有将二者改成原子提交。反馈是可编辑的训练后记录，不属于禁止修改的训练动作/组事实。

## 面试说明：三层机制各解决什么

| 机制 | 本项目中的作用 | 单独使用的局限 |
|---|---|---|
| **事务** | 完成状态与 Outbox 一起提交/回滚；组与离线回执一起提交/回滚；行锁持有到事务结束 | PostgreSQL 默认 READ COMMITTED 下，普通读取不会把“检查 → 写入”串行化，两个事务仍能同时通过检查 |
| **行锁** | 同一训练的修改竞争同一父行，把“状态检查 → 序号分配 → 写入”串行化；先结束则后写入被拒绝 | 所有相关写入口必须遵守协议；锁不会自行验证业务状态，也不能替代事务；持锁时间越长，等待越多 |
| **唯一约束** | 动作 `(workout_id, sequence)`、组 `(workout_exercise_id, set_number)`、回执 `(workout_id, operation_id)` 拒绝重复键；进行中训练的部分唯一索引约束用户 | 无法表达“训练完成后不能增加动作”；重复键异常也不是成功响应重放，不能直接等同于业务幂等 |

可以直接这样讲：**事务保证一组写入一起成功或失败；行锁保证同一训练的竞争写入按顺序检查和修改；唯一约束在数据库层兜住重复数据。三者分别覆盖原子性、并发执行顺序和数据不变量，不能互相替代。**

不使用 JVM `synchronized`，因为多个应用实例不共享同一把 JVM 锁；这里数据已经在 PostgreSQL，父行锁可与业务事务同生共死。没有引入 Redis 分布式锁，也没有把整个库升级为 SERIALIZABLE。边界是同一训练内写入串行，适合当前单用户逐组记录；容量上限需另行测量，不能将本次正确性测试当作性能提升证明。

- 完成/取消分别与新增动作、离线加组、改组、删组竞争：8 个场景。

- 重复完成、重复取消、完成与取消双向竞争：4 个场景，并检查 Outbox 数量。

- 同操作 ID 并发加组：只落一组和一份回执；完成后重放仍成功，新操作被拒绝。
- 反馈等待完成事务提交后成功；跨用户写入拒绝。
- 直接绕过服务插入重复动作序号被数据库拒绝。
