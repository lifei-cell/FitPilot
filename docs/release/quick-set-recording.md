# 沿用上次记录与单击完成一组

日期：2026-09-12

后续更新：数据库级幂等、自动保存及离线恢复已由 [V19 训练恢复功能](workout-auto-recovery.md) 补充；下文 Redis 幂等边界描述的是本功能最初版本。

## 用户流程

开始训练后，每个动作自动查找当前用户在本次训练开始之前，最近一次已完成训练中的有效正式组。按正式组顺序预填重量和次数，点击“完成一组”才创建记录；可先修改再确认。热身组不参与匹配，不沿用 RPE、RIR 或力竭标记。

没有历史时手动填写第一组；超过历史组数时沿用本次最后一个正式组。历史加载失败不影响手动记录。输入后到达的历史结果不会覆盖用户编辑。空白 RPE 不提交，零重量允许用于自重动作。

保存成功立即更新已完成组并预填下一组；失败保留输入。提交期间禁用输入、其他记录操作和完成/取消训练。已有组仍可通过原有编辑、删除入口修正。

## 接口与边界

新增 `GET /api/v1/workouts/{workoutId}/exercises/{workoutExerciseId}/previous-sets`，返回 `SetView[]`，无历史返回空数组。

- 先校验训练所有权和动作属于该训练，再以标准 `exercise_id` 匹配历史，不使用动作名称。
- 只读查询，不修改计划快照或创建已完成组。取消、进行中、其他用户、其他动作以及无有效正式组的训练均不作为来源。
- 按完成时间、训练 ID、动作顺序确定最近动作记录，正式组按原组号排序。不受页面最近 10 次历史限制。
- 写入复用原有 POST sets 接口及后端校验。前端防连点，并为同一载荷的失败重试复用 `Idempotency-Key`。
- 幂等重放依赖已有 Redis 过滤器；Redis 不可用、缓存过期或页面刷新后的不确定提交，不提供数据库级去重保证。本次不扩展离线同步或原生 App。
- 无数据库迁移；现有 Web 手机布局和未来移动端均可使用该接口。

## 验证

执行 `npm run quality --prefix web` 与 `mvn verify`（Windows Docker 使用 `DOCKER_HOST=npipe:////./pipe/dockerDesktopLinuxEngine`）。

新增覆盖：历史预填不写入、逐正式组匹配、手动修改、零重量及空 RPE、失败保留及幂等键重用、防连点、手机视口完整流程；真实 PostgreSQL 集成验证用户与动作隔离、历史选择、热身过滤、空历史和只读性。

本地结果：`mvn verify` BUILD SUCCESS，80 项测试（61 单元 + 19 集成），零失败、零错误、零跳过，覆盖率门禁通过；`npm run quality --prefix web` 通过 lint、TypeScript、39 项组件/单元测试、覆盖率、生产构建和 8 个 Playwright 场景（含 390×844 手机视口）。

首次沙箱验证因 Vite 子进程 EPERM、Docker 管道不可访问而未通过；在批准的沙箱外环境重跑上述完整门禁后通过。远端 CI、镜像发布及生产部署不属于此次完成声明。
