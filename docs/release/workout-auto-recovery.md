# 训练自动保存、恢复与离线记录

完成日期：2026-09-13。适用范围：现有 React Web（含手机布局）及 Spring Boot API。

## 使用方式

1. 联网登录并开始训练。正在填写的重量、次数、RPE 每次修改都会立即保存到本机；预填建议不会自动变成已完成组。
2. 点击“完成一组”或“记录一组”，先持久化确认记录，再尝试上传。离线时仍可记录下一组，页面显示“已保存到本机 · N 组待同步”。
3. 刷新、锁屏或切后台后恢复页面，会读取当前账户的训练快照、草稿和待同步组。生产构建缓存应用静态文件，首次联网缓存完成后可离线重新加载训练页。
4. 联网、回到页面、窗口获得焦点时尝试同步；另有 30 秒定时重试。移动浏览器暂停后台 JavaScript 时不保证后台执行，但本机已落盘内容不依赖后台任务保存。
5. 所有组同步成功、且没有未确认输入后，才允许完成或取消训练。填写中的组可以记录或清空。已有服务器记录的编辑/删除要求联网且没有待同步内容。

登录失效或关闭浏览器导致会话令牌丢失时，需要联网登录原账户再恢复；不会为离线访问而把访问令牌改存 localStorage。不同账户不能看到或上传另一账户的队列。退出登录清除查询缓存，保留账户隔离的本机恢复数据。

## 实现与可靠性

- `workoutRecoveryStore.ts`：按账户隔离的 localStorage 快照、草稿和不可变确认操作。每个确认组使用独立键，避免不同标签页覆盖整条队列。存储失败明确提示，不显示虚假保存成功；损坏数据保留原始内容。
- `QuickSetForm.tsx`：输入即保存，提交时沿用已持久化的操作 UUID；保存失败保留内容。输入草稿和已确认组分开处理。
- `syncWorkoutQueue.ts`：顺序上传；支持 Web Locks 的浏览器在标签页之间互斥，否则依靠后端幂等保证不会重复入库。HTTP 响应丢失、超时、刷新后重试继续使用同一操作 UUID。
- `useWorkoutRecovery.ts`：恢复快照并合并待同步组，处理网络事件、定时重试、登录隔离和完成前检查。每次成功上传后读取服务器事实，持久化快照后才移除队列项。
- `RecoverableSetService` 与 V19：新增 `workout_set_receipt`，在同一数据库事务保存训练组及原始回执。训练行锁串行化同一训练的写入、完成和取消，不依赖 Redis TTL。
- `Client-Operation-Id: <UUID>` 是新增可选请求头，作用于 POST sets。相同编号和载荷返回原回执；不同动作或载荷冲突返回 409。训练已结束或原组已删除后，已成功操作仍可重放回执，不重新插入数据。
- 训练详情中的组返回 `clientOperationId`，用于把服务器已保存的组与本机不确定提交匹配，避免恢复页面暂时显示重复组。
- Service Worker 只缓存版本化静态应用文件，不缓存 API、令牌或私有响应；更新等待旧页面退出，避免强制刷新训练中的页面。

若另一设备结束训练、资源被删除或服务器拒绝数据，会暂停自动同步并保留本机队列，显示原因，允许重试和导出本机记录。不会自动覆盖历史、改变目标训练或丢弃未同步数据。导出文件供人工核对，本次不提供导入与冲突合并。

## 发布与边界

先执行 V19 迁移并完成后端滚动发布，再发布新版 Web，确保所有实例均支持数据库回执。旧版后端会忽略新请求头，不能作为离线同步发布目标。回滚应保留 V19 表结构；存在待同步客户端时不应回退到缺少回执能力的后端。

离线重新打开页面需要 HTTPS（或 localhost）、支持 Service Worker 且已成功缓存应用文件。开发服务器不注册 Service Worker；生产离线测试通过构建后的 preview 运行。清除站点数据、浏览器存储被回收或使用不同浏览器/设备，会丢失本机尚未同步的内容。本次不包含原生 Android/iOS 生命周期验证、离线开始新训练、离线编辑已上传组、离线最终完成训练或系统后台同步。

- 后端完整门禁：`mvn verify`，Windows 配置 `DOCKER_HOST=npipe:////./pipe/dockerDesktopLinuxEngine`。覆盖 V19 迁移、数据库回执、并发重放、Redis 缓存清空、载荷冲突、账户隔离、删除及完成后重放。
- 前端完整门禁：`npm run quality --prefix web`，含 lint、TypeScript、Vitest/覆盖率、生产构建、常规 Playwright 及生产离线 Playwright。
- 新增单元场景：草稿恢复、账户隔离、不可变队列、存储写入失败、响应丢失重试、冲突保留及页面去重。
- 生产离线场景：390×844 视口、断网刷新恢复填写内容、离线连续记录、关闭页面再打开、恢复网络、模拟响应丢失、原操作编号重放及无重复记录。测试恢复登录态，不宣称离线重新认证。
- 浏览器网络事件可能与网络实际恢复时刻不同，测试覆盖最长 30 秒的定时自动重试。测试保留 Service Worker；网络拦截行为参考 [Playwright 官方说明](https://playwright.dev/docs/service-workers)。

上述为本地验证，不代表远端 CI、镜像发布或真实生产部署。
